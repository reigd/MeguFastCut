\# МОДЕЛЬ ПРОЕКТА: МНОГО КЛИПОВ



Проект — \*\*упорядоченная последовательность клипов на одной дорожке\*\*. Это не NLE:

дорожка одна, наложений нет, переходов нет.



```ts

interface SourceFile {

&#x20; id: string;

&#x20; path: string;

&#x20; probe: ProbeResult;          // кодек, разрешение, fps, pixfmt, аудиопараметры, keyframes

&#x20; proxyPath?: string;          // если исходник не играется в WebView2

}



interface Clip {

&#x20; id: string;

&#x20; sourceId: string;

&#x20; inMs: number;                // включительно

&#x20; outMs: number;               // исключительно

&#x20; enabled: boolean;

&#x20; rotate: 0 | 90 | 180 | 270;  // по часовой

&#x20; flipH: boolean;

&#x20; flipV: boolean;

&#x20; cropOverride?: CropRect;     // если не задан — используется глобальный кадр

&#x20; volumeDb: number;            // 0 по умолчанию

}



interface Project {

&#x20; clips: Clip\[];               // порядок = порядок в выводе

&#x20; aspect: AspectSetting;       // глобально

&#x20; fitMode: 'crop' | 'fit' | 'stretch';

&#x20; crop: CropRect;              // глобальный кадр

&#x20; padding: PadSetting;         // цвет или размытый фон

&#x20; output: OutputSettings;

&#x20; audio: AudioSettings;

}

```



Правила:

\- Клипы могут ссылаться на \*\*разные исходные файлы\*\* с разными параметрами.

\- Разрезы (`Split`) порождают новые `Clip` с тем же `sourceId`.

\- Отключённые клипы (`enabled: false`) не попадают в вывод, но остаются в проекте.

\- Порядок меняется перетаскиванием.

\- Если параметры клипов различаются (кодек, разрешение, fps, pixfmt, sample rate,

&#x20; каналы) — приложение обязано показать это пользователю до экспорта и объяснить,

&#x20; что потребуется перекодирование.



\# ТРИ РЕЖИМА ОБРАБОТКИ (ядро продукта)



Режим выбирается \*\*автоматически\*\* по составу правок и показывается пользователю

до старта экспорта вместе с оценкой времени. Принудительное переключение доступно

в расширенных настройках экспорта.



\## 1. Fast (copy) — `-c copy`



Применяется, когда одновременно выполнено всё:

\- все клипы ссылаются на источники с \*\*идентичными\*\* кодеком, разрешением, pixfmt,

&#x20; fps, профилем/уровнем, а также sample rate, кодеком и раскладкой каналов аудио;

\- не менялись пропорции, разрешение, fps, кадр, громкость;

\- контейнер вывода принимает исходные кодеки;

\- точки реза притянуты к ближайшим ключевым кадрам.



Реализация: один клип — `-ss`/`-to` перед `-i` (input seeking) плюс `-c copy`.

Несколько клипов — извлечение сегментов в temp и склейка через \*\*concat demuxer\*\*

с `-c copy`, либо прямой concat demuxer со списком `inpoint`/`outpoint`.

Обязательные флаги: `-avoid\_negative\_ts make\_zero`, `-fflags +genpts`,

`-movflags +faststart` для MP4.



\*\*Поворот в Fast-режиме делается без перекодирования\*\* — через display matrix

(`-display\_rotation` на входе либо `-metadata:s:v:0 rotate=`). Отражение (flip)

в Fast-режиме невозможно и переводит задачу в Re-encode; сообщи это пользователю

бейджем режима, а не ошибкой.



В UI помечается `⚡ Fast · lossless`.



\## 2. Precise (smart cut)



Применяется, когда нужна точность до кадра при обрезке, а всё остальное позволяет copy.

Перекодируются только GOP на краях каждого сегмента, середина копируется, результат

склеивается через concat demuxer. Параметры перекодируемых кусков берутся из probe

исходника, чтобы стык был бесшовным. Помечается `Precise`.



\## 3. Re-encode



Применяется при смене пропорций, разрешения, fps, кодека, при кадрировании, отражении,

разнородных источниках или изменении громкости.



Реализация: \*\*один проход, одна команда ffmpeg, `filter\_complex` с фильтром `concat`.\*\*

Никаких промежуточных файлов и никакого двойного кодирования — это принципиально,

двухэтапная схема ухудшает качество и медленнее.



Скелет графа на каждый клип: `trim`/`atrim` → `setpts`/`asetpts` → `transpose`/`hflip`/

`vflip` → `crop` → `scale` → `pad` (или blur-фон через `split`+`gblur`+`overlay`) →

`setsar=1` → `fps` → `format`, затем общий `concat=n=N:v=1:a=1`.



Аппаратное кодирование: NVENC → Quick Sync → AMF → libx264 как fallback. Доступность

определяется при первом запуске и кэшируется.



\# ЗВУК (обязательные правила, не отступать)



Звук — самая частая причина брака в видеоредакторах. Соблюдай буквально.



\## Главный принцип



\*\*Перекодирование видео НЕ влечёт перекодирования звука.\*\* При смене пропорций,

кадрировании и повороте аудиодорожка копируется как есть (`-c:a copy`), если

контейнер её принимает. Пережимать звук «заодно» запрещено.



\## Когда звук перекодируется



Только при выполнении хотя бы одного условия: клипы ссылаются на источники с разными

параметрами аудио; меняется громкость или включена нормализация громкости; целевой

контейнер не принимает исходный кодек; исходного аудиопотока нет, а у других клипов

он есть; пользователь явно выбрал Re-encode audio.



Во всех остальных случаях — `-c:a copy`.



\## Параметры перекодирования (значения по умолчанию)



| Контейнер | Кодек | Битрейт (stereo) | Примечание |

|---|---|---|---|

| MP4 / MOV / MKV | нативный `aac` (LGPL) | 192 kbps | 5.1 → 384 kbps; mono → 128 kbps |

| WebM | `libopus` | 128 kbps | всегда 48 kHz (ограничение Opus) |

| Только аудио | `libmp3lame` V0 / `pcm\_s16le` / `aac` / `flac` | — | по выбору пользователя |

| GIF | звука нет | — | дорожка отбрасывается молча |



`libfdk\_aac` недоступен (nonfree, исключён из сборки) — не пытайся его вызывать.



\## Частота дискретизации и каналы



\- Частота \*\*сохраняется\*\* (44.1 остаётся 44.1, 48 остаётся 48). Апсемплинг запрещён.

\- Если клипы имеют разную частоту — все приводятся к \*\*наибольшей\*\* из встреченных,

&#x20; через `aresample=resampler=soxr:precision=28`.

\- Для Opus всегда 48 kHz (иначе кодек сам пересчитает хуже).

\- Раскладка каналов сохраняется. Многоканальный звук (5.1) в режиме copy проходит

&#x20; без изменений. Понижение до стерео — только по явному выбору, через

&#x20; `aresample=ochl=stereo` со стандартными коэффициентами, и с предупреждением в UI.

\- Если клипы имеют разное число каналов — все приводятся к наибольшей раскладке

&#x20; (моно дублируется в стерео через `aresample`).



\## Синхронизация



\- При перекодировании: `-af aresample=async=1:first\_pts=0`, для видео `-fps\_mode cfr`

&#x20; при смене fps и `-fps\_mode passthrough` в остальных случаях.

\- При copy и concat demuxer: `-avoid\_negative\_ts make\_zero`, `-fflags +genpts`.

\- Не использовать устаревшие `-async` и `-vsync` — только `-fps\_mode`.

\- После экспорта выполняется автопроверка: длительность аудио и видео в результате

&#x20; расходятся не более чем на 100 мс, иначе задача считается неуспешной и пользователь

&#x20; получает предупреждение с предложением повторить в режиме Re-encode.



\## Стыки клипов



\- При перекодировании на каждый аудиосегмент накладывается \*\*микрофейд 8 мс\*\*

&#x20; на входе и выходе (`afade=t=in:d=0.008`, `afade=t=out:st=<end-0.008>:d=0.008`).

&#x20; Это устраняет щелчки на склейках. Для первого клипа фейд входа не накладывается,

&#x20; если `inMs == 0`; для последнего — фейд выхода не накладывается, если это конец файла.

\- В режиме Fast щелчки на стыках возможны и не лечатся. Если проект содержит более

&#x20; одного клипа и включён Fast, покажи в бейдже режима сноску: «Возможны щелчки

&#x20; на стыках, режим Precise их устраняет».

\- При обрезке AAC в copy-режиме учитывай encoder delay (priming): не паникуй из-за

&#x20; расхождения в пределах 20 мс, но не допускай накопления — проверка длительности

&#x20; выше это ловит.



\## Клипы без звука



Если хотя бы у одного клипа есть аудио, а у другого нет — для беззвучного клипа

генерируется тишина `anullsrc` с целевыми параметрами на его длительность. Иначе

результат получит рассинхрон. Если звука нет ни у одного клипа — аудиопоток

не создаётся вообще, без «пустой» дорожки.



\## Несколько аудиодорожек



По умолчанию берётся первая (`-map 0:a:0?`). Если у источника несколько дорожек,

UI показывает селектор с языком и описанием из метаданных. Для MKV и MOV доступна

опция «Сохранить все дорожки» (только в copy-режиме и при одном источнике).



\## Громкость и нормализация



\- Слайдер громкости в дБ (−30…+12, шаг 0.5, по умолчанию 0). Ненулевое значение

&#x20; переводит звук в перекодирование — покажи это бейджем.

\- Опциональная нормализация громкости (по умолчанию \*\*выключена\*\*), пресеты:

&#x20; Web / Social −14 LUFS, Broadcast (EBU R128) −23 LUFS, Cinema −27 LUFS.

&#x20; Реализация — \*\*двухпроходный\*\* `loudnorm`: первый проход с `print\_format=json`

&#x20; собирает `measured\_I/TP/LRA/thresh`, второй применяет их с `I=<target>:TP=-1.0:LRA=11`.

&#x20; Однопроходный loudnorm использовать запрещено — он даёт нестабильный результат.

&#x20; Второй проход совмещается с основным экспортом, отдельного прохода по видео нет.

\- Опция «Убрать звук» (`-an`).

\- Опция «Извлечь только звук»: если кодек совместим с выбранным контейнером — `-c:a copy`,

&#x20; иначе перекодирование по таблице выше.



\## Метаданные и прочие потоки



\- `-map\_metadata 0` для одного источника; при нескольких источниках метаданные берутся

&#x20; из первого клипа, остальное отбрасывается с пометкой в UI.

\- Субтитры копируются, если контейнер принимает (`-c:s copy`, для MP4 — `mov\_text`);

&#x20; иначе отбрасываются с ненавязчивым уведомлением.

\- Главы сохраняются при одном источнике без разрезов; при склейке отбрасываются.

\- Дата создания и поворот исходника сохраняются.



\# БЕЗОПАСНОСТЬ ДАННЫХ ПОЛЬЗОВАТЕЛЯ (критично)



Видеофайл часто существует в единственном экземпляре. Правила без исключений:



1\. \*\*Исходный файл никогда не открывается на запись.\*\* Всё пишется в новый временный

&#x20;  файл в той же папке (`.megufastcut-tmp-<uuid>`).

2\. Перед любой заменой результат \*\*верифицируется\*\* через ffprobe: файл читается, есть

&#x20;  видеопоток, длительность в пределах ожидаемой ±1 с, размер > 0, расхождение

&#x20;  аудио/видео < 100 мс.

3\. Замена — атомарная (`ReplaceFileW` либо temp + rename), только после верификации.

4\. \*\*Удаление исходника — только в Корзину Windows\*\* (`SHFileOperation` с

&#x20;  `FOF\_ALLOWUNDO`), никогда не безвозвратно.

5\. Любая деструктивная операция требует явного подтверждения и оставляет undo-тост

&#x20;  на 10 секунд.

6\. Временные файлы удаляются при успехе, при ошибке и при старте приложения (уборка

&#x20;  осиротевших по маске `.megufastcut-tmp-\*`). Утечка временных файлов — баг.



\# РАБОТА С FFMPEG



1\. FFmpeg и FFprobe — Tauri sidecar, версия зафиксирована, путь только через sidecar API.

2\. \*\*Аргументы передаются массивом строк. Никогда не собирай командную строку

&#x20;  конкатенацией и не запускай через shell.\*\* Каждый путь — отдельный элемент массива.

3\. Прогресс — из `-progress pipe:1 -nostats`, парсится построчно (`out\_time\_ms`, `frame`,

&#x20;  `fps`, `speed`), транслируется в UI событием не чаще 10 раз в секунду.

4\. Каждая задача имеет токен отмены: отмена = корректное завершение процесса + удаление

&#x20;  частичного файла. Зависших процессов после закрытия приложения быть не должно.

5\. `stderr` пишется в кольцевой буфер (последние 200 строк) и прикладывается к ошибке

&#x20;  раскрывающимся блоком «Технические детали».

6\. Probe: `ffprobe -v quiet -print\_format json -show\_format -show\_streams`, результат

&#x20;  кэшируется по пути + mtime + размеру. Ключевые кадры читаются отдельно

&#x20;  (`-skip\_frame nokey -show\_entries frame=pkt\_pts\_time`) лениво, при первом обращении.

7\. Ошибки переводятся в человеческие сообщения (нет кодека, файл повреждён, нет места

&#x20;  на диске, файл занят). Сырой вывод пользователю в лицо не показывается.

8\. Построение аргументов живёт в одном модуле `src-tauri/src/ffmpeg/args.rs` и покрыто

&#x20;  unit-тестами: на вход — описание задачи, на выход — ожидаемый массив аргументов.

&#x20;  Это главный тестируемый узел приложения.

\- Основной путь: нативный `<video>` в WebView2 через Tauri asset protocol — бесплатное

&#x20; аппаратное декодирование H.264/VP9/AV1.

\- WebView2 не умеет HEVC (без системного расширения), ProRes, DNxHD, часть MKV. При

&#x20; открытии проверяй кодек через ffprobe: если не поддерживается — фоном генерируй

&#x20; \*\*прокси\*\* (H.264, высота 720, CRF 28, faststart) во временную папку, показывай

&#x20; индикатор «Подготовка предпросмотра» и бесшовно подменяй источник, сохраняя позицию.

\- Все правки (обрезка, пропорции, кадр, поворот) применяются к превью \*\*через CSS/Canvas

&#x20; трансформы в реальном времени\*\*, не через перекодирование. Превью реагирует мгновенно.

\- Несколько клипов воспроизводятся как единая последовательность: два `<video>` элемента

&#x20; с предзагрузкой следующего клипа и переключением на границе, чтобы стык не дёргался.

\- Миниатюры генерируются асинхронно, пачками, с приоритетом видимого участка, кэшируются

&#x20; на диск по хешу файла.

\- \*\*Превью обязано совпадать с экспортом по композиции пиксель в пиксель.\*\* Одна и та же

&#x20; модель трансформаций используется и для CSS-превью, и для построения `filter\_complex`.

&#x20; Логика расчёта геометрии живёт в одном месте (`src/shared/geometry.ts`) и покрыта

&#x20; тестами, сверяющими её с параметрами, уходящими в ffmpeg.



\# ЖЁСТКИЕ ТЕХНИЧЕСКИЕ ПРАВИЛА



1\. Никаких блокирующих операций в UI-потоке и в основном потоке Rust: всё тяжёлое —

&#x20;  в задачах с прогрессом и отменой.

2\. Никогда не загружай видеофайл целиком в память. Только потоковая работа и пути.

3\. Ошибки в Rust — `thiserror` + `Result`, без `unwrap()` в продовом пути.

4\. Все длительности внутри — в миллисекундах (`u64`) либо в номерах кадров при известном

&#x20;  fps. Не использовать `f32` для времени. Дробные fps (23.976, 29.97) обрабатываются

&#x20;  как рациональные числа (`24000/1001`), без потери точности на конвертациях.

5\. Undo/Redo — command pattern, покрывает все правки (in/out, split, удаление, порядок

&#x20;  клипов, пропорции, кадр, поворот, громкость). Стек единый, глубина 100.

6\. Производительность UI: 60 fps при скраббинге. Таймлайн рисуется на Canvas, не в DOM.

&#x20;  Никаких React-ререндеров на движение мыши — ref + rAF.

7\. Безопасность Tauri v2: минимальные capabilities, sidecar только для ffmpeg/ffprobe,

&#x20;  валидация путей на стороне Rust, CSP включён.

8\. Все размеры кадра, уходящие в кодек, — чётные. Округляй молча.



\# ЛОКАЛИЗАЦИЯ



Три локали: \*\*`en-US` (по умолчанию и fallback)\*\*, \*\*`en-GB`\*\*, \*\*`uk`\*\*.



\- `src/locales/en-US.json` — полный набор ключей, источник истины.

\- `src/locales/en-GB.json` — \*\*только\*\* строки, отличающиеся от en-US (британская

&#x20; орфография: `colour`, `centre`, `normalise`, `customise`, `behaviour`, `licence`,

&#x20; `grey`). Идентичных значений в файле быть не должно.

\- `src/locales/uk.json` — полный перевод, естественный и профессиональный, без калек

&#x20; с русского, с принятой видеотерминологией («обрiзати», «спiввiдношення сторiн»,

&#x20; «кадрування», «експорт», «роздiльна здатнiсть», «частота кадрiв», «гучнiсть»).

\- Fallback: `en-GB → en-US`, `uk → en-US`. Плюралы — по ICU/CLDR (в украинском 4 формы).

\- \*\*Ни одной строки текста хардкодом в компонентах.\*\* Новая строка добавляется сразу

&#x20; в en-US и uk, в en-GB — только при реальном отличии.

\- Даты, числа, размеры файлов — через `Intl` активной локали. Таймкод

&#x20; (`00:01:23.456`), разрешения, битрейты, fps, LUFS — локале-независимы.

\- Скрипт `npm run i18n:check` падает при недостающих ключах в uk, лишних ключах

&#x20; и при дублях en-GB = en-US. Часть CI.

\- Британская орфография — только в пользовательских строках. Код остаётся американским

&#x20; (`color`, `normalize`, имена токенов и идентификаторов не трогать).



\# ПРОТОКОЛ ВЕРСИЙ И «WHAT'S NEW»



Когда я упоминаю номер версии («версия 1.0.1», «выпускаем 1.1.0»), ты \*\*без напоминания\*\*:



1\. Добавляешь запись в `src/shared/changelog.ts` (единственный источник правды).

2\. Поднимаешь версию в `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`,

&#x20;  `CHANGELOG.md` (Keep a Changelog).

3\. Пишешь текст для `en-US` и `uk`, для `en-GB` — только при реальном отличии. Коротко,

&#x20;  по-человечески, без имён файлов и внутреннего жаргона.

4\. Проверяешь, что мини-вкладка What's New показывает индикатор непрочитанного.

\# ДИЗАЙН-ПРИНЦИПЫ



\- Modern Dark: глубокие нейтральные поверхности, аккуратные слои, один акцент, много

&#x20; воздуха, плавные микроанимации 120–200 ms ease-out.

\- Всё через дизайн-токены (CSS custom properties). \*\*Ни одного хардкод-цвета

&#x20; в компонентах.\*\*

\- \*\*Иконки — только собственные SVG\*\*: stroke-based, `viewBox="0 0 24 24"`,

&#x20; `stroke="currentColor"`, `strokeWidth={1.5}`, `linecap/linejoin: round`, размер через

&#x20; prop. \*\*Эмодзи в интерфейсе запрещены полностью.\*\* Сторонние icon-паки запрещены.

\- Иконки адаптируются к теме через `currentColor` и токены: в Snow толщина 1.6

&#x20; и `--icon-opacity: 0.85` для второстепенных, в Blackout 1.4 и полная непрозрачность,

&#x20; в RGB активная иконка берёт анимированный акцент.

\- Доступность: контраст ≥ 4.5:1, видимый focus-ring, полная работа с клавиатуры,

&#x20; уважение `prefers-reduced-motion`.

\- Layout выдерживает удлинение строк на украинском (+15–30 %): никаких фиксированных

&#x20; ширин под текст, никаких обрезанных подписей.

\- Интерфейс инструментальный, а не «игрушечный»: плотно, точно, попадание курсором

&#x20; предсказуемое.



\# ФОРМАТ ТВОИХ ОТВЕТОВ



\- Выдавай \*\*полные файлы целиком\*\*, с указанием пути в заголовке блока кода.

\- Запрещено: `// ... остальной код без изменений`, `// TODO: реализовать позже`,

&#x20; многоточия вместо кода, псевдокод, пустые заглушки функций.

\- Перед крупной задачей — список файлов, которые создашь или изменишь (просто список).

\- После задачи — короткий отчёт: что готово, как проверить руками, что дальше.

&#x20; Максимум 10 строк.

\- Не переписывай файлы, которых задача не касается. Не рефактори «заодно».

\- Если требование технически невыполнимо или опасно для данных пользователя — скажи

&#x20; прямо одним абзацем и предложи рабочую альтернативу.



\# ЧЕГО НЕ ДЕЛАТЬ



\- Не превращать FastCut в полноценный NLE: никаких нескольких дорожек, наложений,

&#x20; переходов, эффектов, цветокоррекции, титров, ключевых кадров, кривых.

\- Не перекодировать там, где достаточно `-c copy`. Не пережимать звук «заодно».

\- Не трогать исходный файл на запись ни при каких обстоятельствах.

\- Не делать двухэтапное перекодирование при склейке (двойная потеря качества).

\- Не добавлять телеметрию, аккаунты, облако и сетевые запросы (исключение — отключаемая

&#x20; проверка обновлений).

\- Не оставлять мёртвый код, закомментированные блоки и дубли.

\- Не описывать словами то, что просили сделать кодом.
